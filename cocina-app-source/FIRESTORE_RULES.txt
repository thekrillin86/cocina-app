ESTADO ACTUAL (las que están publicadas ahora mismo)
----------------------------------------------------------
Sirven, pero conviene saber qué protegen y qué no.

La app entra con signInAnonymously(), así que "request.auth != null"
lo cumple CUALQUIERA que abra la web: la configuración de Firebase va
en el JavaScript publicado (es pública por diseño) y con ella se puede
pedir un usuario anónimo desde fuera de la app.

Consecuencia: hoy la base de datos es legible y escribible por
cualquiera que se moleste en mirar el bundle, y el PIN de /config/auth
se puede leer en claro. El PIN es una puerta de cortesía en el
cliente, no una medida de seguridad.

Para un recetario familiar el riesgo es bajo, pero está aquí escrito
para que sea una decisión y no un descuido.

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // /config/auth — PIN familiar
    match /config/{doc} {
      allow read: if request.auth != null;
      allow write: if false;
    }

    // /menus — menús semanales
    match /menus/{weekId} {
      allow read, write: if request.auth != null;
    }

    // /shopping-lists — listas de la compra
    match /shopping-lists/{listId} {
      allow read, write: if request.auth != null;
    }

    // /recipes — recetas del recetario
    match /recipes/{recipeId} {
      allow read, write: if request.auth != null;
    }
  }
}


==========================================================
BUZÓN DE RECETAS  /inbox/{loteId}
==========================================================

El asistente deja lotes de recetas desde fuera de la app y Juan los
aprueba en el móvil. Hay que AÑADIR este bloque a las reglas de
arriba; sin él la app avisa de que no puede leer el buzón.

    // /inbox — lotes de recetas dejados por el asistente
    match /inbox/{loteId} {

      // Cualquiera autenticado puede DEJAR un lote, con la forma exacta
      allow create: if request.auth != null
        && request.resource.data.keys().hasOnly(
             ['createdAt','source','batch','status','recipes'])
        && request.resource.data.status == 'pending'
        && request.resource.data.createdAt is string
        && request.resource.data.source is string
        && request.resource.data.source.size() <= 60
        && request.resource.data.batch is string
        && request.resource.data.batch.size() <= 60
        && request.resource.data.recipes is list
        && request.resource.data.recipes.size() > 0
        && request.resource.data.recipes.size() <= 50;

      // Leer, aprobar y descartar, solo desde la app
      allow read, update, delete: if request.auth != null;
    }

Qué protege y qué no
--------------------
La forma del documento sí: quien escriba no puede meter campos
inventados, ni marcar un lote como ya revisado, ni mandar más de 50
recetas de golpe (un documento de Firestore son 1 MiB).

Quién escribe, no. `request.auth != null` lo cumple cualquiera,
porque el acceso anónimo está abierto. Hoy eso no añade ningún
agujero nuevo —la base de datos entera ya está así—, pero conviene
saber que cualquiera podría dejar lotes en el buzón.

Lo que sí protege de verdad es que el buzón está en cuarentena: la
app lo enseña para revisarlo y no aplica nada sola. Nada entra en el
recetario sin que Juan lo apruebe.


==========================================================
MEJORA RECOMENDADA: dos cuentas reales
==========================================================

Cierra el agujero de arriba. NO pegues estas reglas hasta haber
completado los pasos 1 y 2, o te quedas fuera de tu propia app.

PASO 1 — Crear las dos cuentas
  Consola de Firebase → Authentication → Sign-in method
    · Activar "Correo electrónico/contraseña"
    · (Opcional) desactivar "Anónimo" cuando ya no se use
  Authentication → Users → Add user
    · Crear la cuenta de Juan y la de Magda
    · Copiar el UID de cada una (columna "User UID")

PASO 2 — Cambiar el login de la app
  Sustituir signInAnonymously() por signInWithEmailAndPassword()
  en src/AuthGate.jsx: pedir correo y contraseña en vez del PIN.
  Firebase ya guarda la sesión (browserLocalPersistence), así que
  se seguirá pidiendo solo la primera vez en cada móvil.

PASO 3 — Publicar estas reglas, con los UID reales
  Consola de Firebase → Firestore Database → Rules

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Solo estos dos usuarios, por UID
    function esDeCasa() {
      return request.auth != null && request.auth.uid in [
        'UID_DE_JUAN',
        'UID_DE_MAGDA'
      ];
    }

    // Con cuentas reales, /config/auth ya no hace falta:
    // el PIN deja de existir. Se deja cerrado del todo.
    match /config/{doc} {
      allow read, write: if false;
    }

    match /menus/{weekId}        { allow read, write: if esDeCasa(); }
    match /shopping-lists/{listId} { allow read, write: if esDeCasa(); }
    match /recipes/{recipeId}    { allow read, write: if esDeCasa(); }

    // El buzón: leerlo y vaciarlo es cosa de casa, dejar lotes no
    match /inbox/{loteId} {
      allow create: if esElAsistente()
        && request.resource.data.keys().hasOnly(
             ['createdAt','source','batch','status','recipes'])
        && request.resource.data.status == 'pending'
        && request.resource.data.recipes is list
        && request.resource.data.recipes.size() > 0
        && request.resource.data.recipes.size() <= 50;

      allow read, update, delete: if esDeCasa();
    }

    // Todo lo demás, cerrado
    match /{document=**} { allow read, write: if false; }
  }
}

QUIÉN ES EL ASISTENTE — la decisión de la fase 4
------------------------------------------------
Al cerrar el resto con esDeCasa(), el buzón se queda siendo la única
puerta abierta. Hay dos formas de cerrarla, y conviene elegir:

  A) Dejarla abierta a cualquier anónimo (lo que proponía el brief)

       function esElAsistente() { return request.auth != null; }

     No hay que pasarle ninguna credencial al asistente, pero hay que
     mantener activado el proveedor anónimo en la consola de Firebase
     y cualquiera puede dejar lotes. Sigue sin poder leer ni tocar
     nada, y tú decides qué entra.

  B) Darle su propia cuenta (recomendado)

       function esElAsistente() {
         return request.auth != null && request.auth.uid == 'UID_DEL_ASISTENTE';
       }

     Authentication → Users → Add user, una cuenta solo para esto.
     El asistente entra con accounts:signInWithPassword en vez de
     accounts:signUp, y el proveedor anónimo se puede DESACTIVAR del
     todo. Hay que darle un correo y una contraseña, pero es una
     cuenta que solo puede crear lotes en el buzón: no lee, no borra
     y no toca nada más.

Con la opción A hay que dejar el acceso anónimo activado. Con la B no,
y es la única que cierra la casa entera.

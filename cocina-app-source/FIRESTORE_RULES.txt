==========================================================
REGLAS DE FIRESTORE — proyecto cocina-juanlc
==========================================================

Las reglas deciden quién puede leer y escribir en la base de datos.
Se publican a mano en la consola de Firebase:

    console.firebase.google.com
      → proyecto cocina-juanlc
      → Firestore Database
      → pestaña Rules / Reglas
      → pegar, Publicar

Este fichero lleva los identificadores con hueco (UID_DE_JUAN y
compañía) porque el repositorio es público. Los de verdad se pegan
solo en la consola. No son secretos —saber un identificador no deja
entrar a nadie, hace falta la contraseña— pero tampoco pintan nada
en GitHub.

==========================================================
3. LAS REGLAS FINALES
==========================================================

Sustituir los tres huecos por los identificadores reales.

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Las dos personas de la casa
    function esDeCasa() {
      return request.auth != null && request.auth.uid in [
        'UID_DE_JUAN',
        'UID_DE_MAGDA'
      ];
    }

    // La cuenta que usa el asistente, solo para dejar lotes
    function esElAsistente() {
      return request.auth != null && request.auth.uid == 'UID_DEL_ASISTENTE';
    }

    // El PIN ya no se usa. Cerrado del todo.
    match /config/{doc} {
      allow read, write: if false;
    }

    match /menus/{weekId}          { allow read, write: if esDeCasa(); }
    match /shopping-lists/{listId} { allow read, write: if esDeCasa(); }
    match /recipes/{recipeId}      { allow read, write: if esDeCasa(); }

    // El buzón: el asistente solo puede DEJAR lotes, con esta forma
    // exacta. Ni los lee, ni los cambia, ni los borra.
    match /inbox/{loteId} {
      allow create: if esElAsistente()
        && request.resource.data.keys().hasOnly(
             ['createdAt','source','batch','status','recipes'])
        && request.resource.data.status == 'pending'
        && request.resource.data.createdAt is string
        && request.resource.data.source is string
        && request.resource.data.source.size() <= 60
        && request.resource.data.batch is string
        && request.resource.data.batch.size() <= 60
        && request.resource.data.recipes is list
        && request.resource.data.recipes.size() > 0
        && request.resource.data.recipes.size() <= 50;

      allow read, update, delete: if esDeCasa();
    }

    // Todo lo demás, cerrado
    match /{document=**} { allow read, write: if false; }
  }
}

==========================================================
5. CÓMO ESCRIBE EL ASISTENTE
==========================================================

Por la API REST de Firestore, con la cuenta del paso 1:

  1. Pedir un token
       POST https://identitytoolkit.googleapis.com/v1/
            accounts:signInWithPassword?key=<apiKey web>
       { "email": "...", "password": "...", "returnSecureToken": true }

  2. Dejar el lote
       POST https://firestore.googleapis.com/v1/projects/cocina-juanlc/
            databases/(default)/documents/inbox
       Authorization: Bearer <idToken del paso 1>

La apiKey web es la que ya está en src/firebase.js y es pública por
diseño. El correo y la contraseña del asistente, no: son la única
credencial del montaje y solo la necesita quien envía los lotes.

Máximo 50 recetas por lote, porque un documento de Firestore son
1 MiB. Si hay más, se parten en varios.

El documento tiene esta forma exacta:

  {
    createdAt: '2026-09-17T05:10:00.000Z',
    source: 'talaia',
    batch: 'lote-02',
    status: 'pending',
    recipes: [ ... ]
  }

Y cada receta:

  {
    name: 'Frittata de pollo',
    type: 'comida' | 'cena',
    category: 'huevos',            // ensalada, pescado, carne, pasta,
                                   // arroz, legumbres, huevos, crema,
                                   // verduras, otro
    proteins: 'Pollo y huevo',
    calories: 260,
    rating: 0,
    source: 'Cookidoo',
    recipe: {
      method: 'Thermomix TM6',
      source: 'https://cookidoo.es/...',
      ingredients: ['Huevo 4ud', 'Pimiento rojo 200g'],
      steps: ['🔧 Método: ...', 'Batir los huevos']
    }
  }

Obligatorios solo `name` y `type`. El resto se rellena solo: la
categoría se adivina por el nombre, y los ingredientes y pasos se
admiten también como texto con saltos de línea.

Un nombre que ya esté en el recetario se fusiona con su ficha en vez
de duplicarse, y solo se escribe lo que traiga el JSON: no se pierden
valoraciones ni recetas.


==========================================================
6. VUELTA ATRÁS DE EMERGENCIA
==========================================================

Si algún día las reglas del punto 3 dejan a todo el mundo fuera —por
ejemplo, si se borra por error una de las cuentas y hay que
recrearla—, esto devuelve el acceso mientras se arregla. Abre la base
de datos a cualquiera que se autentique, así que es un parche
temporal, no un sitio donde quedarse.

Requiere volver a activar el acceso anónimo SOLO si además hay que
usar una versión antigua de la app; con la versión actual basta con
las cuentas de correo.

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /menus/{weekId}          { allow read, write: if request.auth != null; }
    match /shopping-lists/{listId} { allow read, write: if request.auth != null; }
    match /recipes/{recipeId}      { allow read, write: if request.auth != null; }
    match /inbox/{loteId}          { allow read, write: if request.auth != null; }
  }
}
